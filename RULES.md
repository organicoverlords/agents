Producer review may record `NOT_PROVEN` or `REJECTED` with concrete visible findings, but the producer must never promote its own capture to `PROVEN`; final `PROVEN` remains an independent visual review. A rejected capture remains diagnostic evidence; rerender the affected claim rather than relabeling the rejected artifact.
- Machine-route precedence: prefer MCPv4 when healthy and exposed. Normal filesystem/process/Git/GitHub work uses the machine route; for GitHub repositories, use local `git`/`gh` through MCPv4 and do not require a direct GitHub plugin. A rejected MCPv4 command shape is route/argument state rather than capability loss. MCPv4 discovery/rebinding is repeatable, not a single-use event: when the binding is absent, stale, disconnected, or a discovery attempt fails transiently, refresh/re-discover only the binding needed, retry the smallest supported invocation, and use bounded backoff rather than repeating an unchanged failing call. A failed discovery/rebind attempt is never by itself a run-end condition. When MCPv4 is genuinely unavailable, fall back in order to MCPv3, then Remote Desktop Commander for machine operations, then a direct GitHub plugin/connector for GitHub operations when available, and periodically retry MCPv4 discovery during ongoing work so transient route loss can recover within the same run. MCPv3, Commander, and direct GitHub are fallback routes rather than co-primary routes; `retired` means fallback-only/not primary, not forbidden.
- GitHub read acceleration is local-first and Rust-backed. For noninteractive tools that issue repeated safe read-only GitHub CLI lookups, prefer the installed Rust `ghbuf exec -- <command>` lane when available; it may cache/coalesce only provably read-only calls and the unchanged child command remains the unit of execution. Do not globally shadow or replace interactive `gh`; interactive or mutating commands keep real GitHub CLI semantics, and cache failure degrades only through the owning supported route rather than becoming permission. Remote nodes without authenticated GitHub may use only `ghbuf exec-readonly -- <command>` through an authenticated loopback tunnel; pass explicit `--repo`/`GH_REPO` when repository identity cannot be derived on the Windows sidecar, and ambiguous or mutating commands fail closed. GitHub/repo state remains authoritative; cache hits, stale values, metrics, and refresh state are acceleration evidence only and never work, liveness, ownership, progress, or permission. This does not authorize repeated polling; reuse fresh answers under the existing bounded-read rule.
- A tool or route failure is local contention, not by itself a run-end condition. Continue the required operation through an exposed approved route when that is best; repair the failed owner when appropriate; otherwise checkpoint the contribution and select another ready canonical issue/North-Star contribution. Do not loop an unchanged failed route, do not treat the current issue as a worker-owned lane, and do not invent unrelated work merely to stay active. Yield for the failure only when no approved route, no safe blocker repair, and no ready canonical contribution can advance the established project/product goal.
